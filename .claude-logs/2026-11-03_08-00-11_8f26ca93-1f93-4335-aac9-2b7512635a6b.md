Every `git push` waits on `.githooks/pre-push`, which runs six full-repo checks one after another and prints nothing until each one finishes. A one-line change still pays for the whole tree.

The hook runs, in order: `format:check`, `lint`, `typecheck`, `check:env`, `check:events`, then `test`. Each is a separate `npm run`. The next one starts only after the previous one exits. `check:env` and `check:events` are cheap file walks. Almost all of the time is the other four.

**Format and lint scan everything.** `prettier --check .` and `eslint .` both walk the repo. ESLint loads two heavy configs at once — Next.js (`next/core-web-vitals` and `next/typescript`) for `apps/web`, and Expo’s flat config for `apps/mobile` — and the TypeScript import resolver points at both apps’ `tsconfig.json` files. That startup cost is paid on every push.

**Typecheck is four compilers in a row.** The root script runs `tsc --noEmit` for web, mobile, `@app/contract`, and `@app/brand`, each through its own `npm run`. Only the web `tsconfig.json` has `"incremental": true`. Mobile, the contract package, and brand typecheck from scratch every time.

**Tests are the long pole.** `npm test` chains four suites with `&&`:

- Every `scripts/*.test.mjs` file. `scripts/check-standards.test.mjs` is about 2,100 lines. It copies fixture repos, spawns `git` and the standards script, and at least once builds a full ESLint instance against this repo and runs the standards checker on the real tree.
- Mobile Jest through `jest-expo`, which also runs `packages/brand`. Jest’s Expo preset transforms React Native on a cold start; that startup alone is often the single longest step.
- The web suite, about 25 `*.test.mts` files loaded through a TypeScript register hook.
- The contract package tests, the same way.

**It looks frozen while it runs.** The hook stores each command’s entire output in a shell variable (`out=$(npm run …)`) and only prints the last 25 lines if that gate fails. Git sits quiet for the whole of Prettier, ESLint, the four `tsc` runs, and Jest.

On Windows each of those `npm run` calls also pays a slow process start, and typecheck and test nest more of them. The production Next.js build, the standards check, the store check, and the database replay are not in this hook — they live in `/local-review`. The push is already this slow without them. The hook is written that way on purpose: it is the local copy of CI’s compile, lint, and test gates, so a format or type error is caught here instead of in a paid GitHub Actions run.

The sequential order is intentional, and running the six checks at once would fight it. The plan no longer does that.

The hook in `.githooks/pre-push` is a shared template script. It is a straight list — format, lint, typecheck, env, events, then tests — so the same file works with npm, pnpm, or yarn, and so a repo that lacks one of those scripts skips it instead of failing. Format is first because that is the usual miss, and the failure text tells you to run `npm run format`. Tests are last because they are the expensive confirmation. The local-review skill says to stop at the first failure rather than stack up several unrelated ones. A sequential hook is what makes that possible: one command fails, and you see the last 25 lines of that command. Six logs at once would bury that.

A push that actually passes still runs every check, on the whole tree. The thing being pushed is the whole tree, so a gate that only looked at the files in the last commit would miss a break in a file the change did not touch.

That design assumes those commands are cheap. They are not in this repo. Typecheck is four compilers, lint loads both the Next.js and Expo ESLint configs, and `npm test` includes `scripts/check-standards.test.mjs`. About 45 of those tests each copy every tracked file into a fresh temporary repo, then run `git init` and `git add`, and Node runs those copies at the same time. The copy itself is required: the test is named so that a fixture taken from this repo passes, and a later failure is caused by that test's mutation. Each case needs its own tree. Rebuilding that tree from scratch 45 times is the cost the template hook was not written to absorb.

So the hook stays as it is. Two changes sit inside the commands it already calls:

- ESLint, Prettier, and `tsc` remember unchanged files. The first push in a checkout still scans everything. The next one rechecks what changed. CI starts with an empty cache, so it still does a full scan.
- The standards tests build one template repo and copy that for each case, instead of recreating the repo 45 times. Each test still mutates only its own copy.

Stopping at the first red check would only shorten a push that is already failing. A push that passes, which is the ~10 minute case, still has to run all six.
