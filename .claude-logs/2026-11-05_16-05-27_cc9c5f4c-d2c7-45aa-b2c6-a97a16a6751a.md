Logs were not being created properly, and the hooks were also overwriting the wrong file. I've fixed the script.

**What was wrong**
- The hooks do run in this new session. But [extract-log.py](.claude/hooks/extract-log.py) decided which session to log by picking the most recently changed transcript.
- When you send a prompt, the hook runs before Claude Code writes the new session's transcript. So the newest transcript was still the previous session's. At 16:04:19, when you sent this prompt, it rewrote the previous session's log (`2026-11-05_15-58-53_ae2b82eb…md`) and made no log for this session. That broke the promise not to touch other sessions' files. The content came out the same this time, but with several sessions open at once it could mix up their logs.

**The fix**
- Claude Code tells each hook which session it belongs to (`session_id` and `transcript_path`). The script now uses that.
- It only falls back to "newest transcript" when you run it by hand.
- When you send a prompt, it also logs your prompt straight away, so a session's log file appears on its first message rather than waiting for the end of the turn.
